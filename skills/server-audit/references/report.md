# 报告结构与分级

## 结构

```
一句话结论（能不能被攻破、最坏结果是什么）
一、证据与实测（表格，每条写明命令和结果）
二、逐台风险清单（P0 / P1 / P2，每条四段：证据 → 影响 → 怎么改 → 怎么验）
三、30 分钟能做完的
四、30 天计划
五、未验证（读不到的、没做的、需要人确认的）
```

## 每条怎么写

- **证据**：必须是命令输出或配置文件行号，不能是「看起来」「可能」。
- **影响**：说清丢什么（数据/权限/钱/时间），不要写「存在安全风险」。
- **怎么改**：给命令或后台路径，一步一条，能复制。
- **怎么验**：改完跑什么命令、看到什么算成功。

## 分级口径

见 `checks.md` 末尾。同一条风险在不同机器上等级可以不同——公网机器上的 P2，内网机器上可能只是备注。

## 写作禁忌

- 不写「全面提升安全水位」这类空话。
- 不把「未验证」写成结论。
- 不隐藏「修不了」的项：写清为什么修不了（业务冲突、需要停机、没人手）。
